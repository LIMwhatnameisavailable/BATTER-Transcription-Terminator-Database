# BTED v0.1 local snapshot 发布说明

**发布日期：** 2026-08-10
**范围：** 将本地 BGIRNA 工作树中已整理的 BATTER Table S1 结果转化为可由 Git 追踪、可自动校验的首个 BTED 发布快照。

## 本次发布回答了什么问题

此前仓库有 22 来源注册表、文献笔记和协作模板，但没有端点级标准数据、来源级 manifest 或逐来源处理记录。因此“本地已经做过什么”和“协作者可以从 Git 得到什么”之间存在断层。

本版建立了这条连接：每个来源都有明确的发布状态；适合公开的结果转为统一 24 列 TSV，实验端点另有规范 BED；不适合公开端点层的资产只留 checksum 审计证据，不混入数据下载。

## 发布规模

| 指标 | 数量 | 说明 |
|---|---:|---|
| BATTER S1 来源 | 22 | 对应 13 篇原始研究文献；两个口径不混写 |
| `published_standardized` 来源 | 21 | 共 28,399 条标准化记录 |
| `author_called_endpoint` 来源 | 17 | 作者发表的实验 3′ end 表；各有 TSV 与 BED |
| `curated_record` 来源 | 4 | Lalanne 2018 的文献整理记录；仅 TSV，不在本版生成 BED/JBrowse |
| `audit_only` 来源 | 1 | `BATTER_S1_002`，尚未完成公开 schema 所需的逐数据集 provenance 对齐 |
| Git 内 JBrowse/BigWig | 0 | 大型浏览器资产不随本版 Git 发布 |

逐来源判定见 [`data/registry/batter_s1_publication_status.tsv`](../../data/registry/batter_s1_publication_status.tsv)，所有文件及 SHA-256 见 [`data/public/release_manifest.v0.1-local-snapshot.json`](../../data/public/release_manifest.v0.1-local-snapshot.json)。

## 目录与可复现性

```text
data/public/records/<source_id>/   可公开的标准 TSV；实验端点另有 BED
data/public/release_manifest...    发布级计数、输入/输出 checksum 与决策
data/audit/excluded_assets/        未公开资产的行数、SHA-256、证据与原因
data/registry/manifests/           22 个来源的机器可读 manifest
docs/sources/<source_id>/          逐来源发布判定与处理记录
scripts/build_local_snapshot_release.py
scripts/validate_bted_release.py
```

生成命令（仅在持有经审计的本地 BGIRNA 快照时运行）：

```bash
python3 scripts/build_local_snapshot_release.py --input-root /path/to/BGIRNA
python3 scripts/validate_bted_release.py
```

构建器只读取本地派生结果和 manifest，生成 Git 可追踪的小型发布资产；它不复制原始测序、工作簿、FASTA/GFF、BigWig 或 JBrowse 文件。

## 证据边界

1. `author_called_endpoint` 与 `curated_record` 的表分别标记，不能用同一种文字概括为“功能验证的终止子”。
2. `BATTER_S1_002` 的作者整合 TRS 表不在 `data/public/`；它和待对齐的观察表仅在审计 manifest 中留存可复核指纹。
3. `BATTER_S1_020` 的 Nanopore 端点可公开，但其 S1C 混合实验/预测表不公开。
4. `BATTER_S1_022` 的作者 Term-seq TTS 可公开；纯 RhoTermPredict RUT 表不公开。
5. 预测支持作为作者表中的附属注释时不改变端点的主要证据等级；纯预测表永不进入公开端点层。

详见 [证据分层与发布边界](../standards/证据分层与发布边界.md)。

## 已知限制与下一步

- 这是可审计的数据发布快照，而不是部署完成的生产数据库。GitHub Pages 仍只展示元数据目录；JBrowse 需要以独立版本化浏览器包发布。
- 原始数据可访问性、出版商补充材料再分发限制，以及部分来源的精细许可仍须在正式外部发布（例如 Zenodo）前逐项复核。
- `BATTER_S1_005`、`BATTER_S1_022` 需要补充详细来源处理 Markdown；这不影响已经记录的当前发布判定，但应在下个小版本补齐。
- `BATTER_S1_002` 最重要的下一步是明确每条数据集级观察的作者表行/样本/坐标 provenance，只有能够拆出纯实验端点时才可从 `audit_only` 变成公开数据。
