# GitHub Pages Demo Plan

**Task:** 01 deliverable — plan only. The site itself is built in Task 02, after this plan and the migration inventory are reviewed.
**Date:** 2026-08-07

---

## 1. Scope and hard boundary

A small, static, reviewable demonstration of the BTED database, deployed as a project site under `/<repository-name>/`.

- GitHub Pages is **static hosting only**: there is **no server-side database, no server-side code, and no private-data access**. Any search/filter runs client-side on a generated public metadata file.
- The demo exposes **approved public metadata and small derived assets only**. Raw sequencing data and publisher workbooks are never part of the Pages artifact; the site links to GEO/SRA/ENA/ArrayExpress/Figshare/PRIDE/Zenodo via the verified accessions in `accession_list_verified.csv`.
- Every scientific statement on the site links to a repository document or a primary source. Anything depending on the external BTED working state is deferred until verified (see `docs/current-bted-status.md`); the site must not create placeholder scientific claims.
- The site never labels prediction-only or mixed-evidence records as experimentally validated endpoints. BATTER genome-wide predictions (Zenodo `TES.bed.gz`) are clearly marked as predictions if mentioned at all.

## 2. Page map

1. **Home** (`index.html`)
   - Project purpose: a database of experimentally supported bacterial transcription terminators built from the 13 verified source papers.
   - Evidence boundary and scope statement; source count/version shown exactly as approved (currently: 13 papers verified, per `data_verification_report.md`).
   - Limitations summary and link to the methods page.
2. **Data catalog** (`catalog/`)
   - Static, client-side searchable/filterable table generated from an **approved** metadata file (see Section 3).
   - Columns bounded to verified metadata: PMID, species/strain, assay type, accession(s), coordinate-file status, citation/DOI.
3. **Record page template** (`records/<pmid>.html`, one per source or a documented template)
   - Organism, assay, reference genome, evidence class (only after the SOP is approved), status, public download links, citation, external source links.
   - Generated from the same approved metadata file; no hand-written per-record claims.
4. **Methods / limitations** (`methods/`)
   - Coordinate conventions and open standardization decisions (linking `docs/current-bted-status.md`), evidence-layer definitions once approved, exclusions, reproducibility links.
5. **Optional JBrowse link**
   - Added only when the corresponding public JBrowse configuration and assets are verified (`to verify` today). If unverified at Task 02 time, the link is omitted entirely, not stubbed.

## 4. External raw-data links

The site links out, never copies:

- Per-source raw data: accessions from `accession_list_verified.csv` (GEO/SRA/ENA/ArrayExpress/Figshare/PRIDE/GenBank).
- BATTER model artifacts: Zenodo DOI 10.5281/zenodo.16761763, labeled as training data/predictions per `report_zenodo_and_documents.md`.
- Publisher supplementary files: cited by DOI per source.

All outbound links are checked during validation (Section 6).

## 5. Deployment approach

- Site source lives in a dedicated directory (e.g. `site/`) on a Task 02 branch; a GitHub Actions workflow builds a **dedicated static artifact** and deploys it to Pages. No deployment directly from an experimental working directory.
- All asset and link paths are **relative** and valid under the project subpath `/<repository-name>/`; never assume serving from `/`.
- Large raw inputs stay outside the artifact; the workflow fails if an unexpected large/binary file enters the artifact (size check step).
- No credentials, tokens, unpublished data, local absolute paths, or cache directories in the deployed artifact.

## 6. Validation plan (Task 02)

1. Run any regression tests supplied by the accepted migration (none exist in this repository today).
2. `git diff --check` clean.
3. Serve the site locally under a `/<repository-name>/` subpath (e.g. `python3 -m http.server` with a path prefix or an equivalent static server) and verify:
   - home page loads at the subpath;
   - catalog search/filter works client-side;
   - all internal links are relative and resolve;
   - at least one record page renders;
   - JBrowse link present only if verified, and loads;
   - outbound accession/DOI links return success (spot-check);
   - no page labels predictions or mixed evidence as experimental endpoints;
   - artifact size and file-type scan show no raw data, credentials, or local paths.
4. Include screenshots and the exact local validation commands in the draft PR.

## 7. Explicitly out of scope for the demo

- Any server-side component, database, login, or private-data access.
- Importing standardized coordinate data or JBrowse tracks before the Task 01 acceptance gate is passed.
- Copying publisher workbooks or sequencing data into the repository or the Pages artifact.
