# 协作者指南：新增文献收集与入库

这是一份照着做就能完成的教程。你不需要事先了解本项目的全部历史，只需要按步骤执行、如实记录。遇到任何无法核实的信息，停下来标记，比猜一个答案更有价值。

**任务目标：** 把一篇新的、含实验支持的细菌转录 3′ end 数据的文献，按统一格式登记并（在核验通过后）标准化入库，最终以 Pull Request 的形式交给项目评审合并。

## 0. 开始前

读三样东西：

1. 本指南；
2. [数据字段字典](数据字段字典_v0.1.md)（填表时随手查）；
3. [证据分层与发布边界](证据分层与发布边界.md)（知道什么能公开、什么不能）。
4. 若你接手的是已完成资料搜集的一批外部来源，再读[外部来源正式整合入库要求](外部来源正式整合入库要求_v0.1.md)；它说明如何交接，而不是直接整体合并分支。

准备工具：一个文本编辑器、能上网查文献和数据库的浏览器、命令行（计算校验和用）。不需要装任何专门的生信软件来完成“登记”这一步。

## 1. 总流程

```
判断文献是否适合收录
  → 找到原始数据与补充表
  → 填来源登记表（26 列）
  → 核对菌株 / 参考组装 / contig / 坐标体系 / 链方向
  → 核验通过？ 否 → 标记 to_review / blocked，到此为止
             是 ↓
  → 建端点表（24 列），保留作者原始表
  → 记录 checksum、处理过程与问题
  → 建 feature 分支，提交，开 Draft PR
```

## 2. 第一步：判断文章是否适合收录

同时满足以下条件才收录：

- 研究对象是**细菌**（含古菌可先在 Issue 里询问）；
- 包含**实验产生的转录 3′ end / TTS / terminator 数据**：如 Term-seq、Rend-seq、dRNA-seq（直接 RNA 测序）、3′ end sequencing、SEnd-seq 等；
- 数据**公开可获取**：补充表里有坐标，或 GEO/SRA/ENA/ArrayExpress 有原始数据；
- 坐标能对应到**明确的参考基因组**。

以下情况不收录或暂缓：

- 纯计算预测（没有实验数据）：不入库；
- 只有表达量、没有 3′ end 坐标：不入库；
- 数据“available upon request”且无公开链接：登记为 `blocked`，写明原因；
- 真核生物：不在本项目范围。

拿不准时：先填来源登记表，把 `processing_status` 设为 `to_review`，在 PR 里说明疑点，由评审决定。

## 3. 找原始数据与补充表

按这个顺序找：

1. **论文的 Data Availability / Availability of data 声明**（正文末尾）：这里通常直接给出 GEO/SRA/ENA/ArrayExpress/Figshare/Zenodo 登录号；
2. **出版商网站的 Supplementary Materials 页面**：下载补充表（xlsx / csv / pdf），记录文件名；
3. **PubMed / PMC**：PMID、DOI、PMC 全文链接；
4. **GEO（ncbi.nlm.nih.gov/geo）**：用 GSE 号查样本（GSM）与平台，确认物种、菌株、文库策略；
5. **ENA / SRA**：用 RUN/PROJECT 登录号核对原始 reads 对应的样本描述；
6. **作者自己的仓库**（GitHub / Zenodo / Figshare）：可能有处理后的坐标表。

把找到的所有登录号原样抄进来源登记表的 `raw_data_accessions`；把能直接打开文件的链接放进 `raw_or_supplement_url`；把补充表文件名放进 `endpoint_source_file`。

## 4. 填写来源登记表

模板：`data/registry/templates/external_literature_source_intake.tsv`（26 列，制表符分隔）。**复制模板文件再填，不要改模板本身。**

一行 = 一个可独立处理的来源。同一篇论文里有两个物种 / 两种菌株 / 两套实验体系 / 两个参考版本时，拆成两行（或多行），每行各自的 `source_id` 不同。

### 4.1 第一时间要填的列（最小登记门槛）

| 列 | 说明 |
|----|------|
| `source_id` | `BTED_EXT_年份_三位序号`，如 `BTED_EXT_2026_001`；先查 `data/registry/` 与 `docs/WORKLOG.md` 确认序号没被占用 |
| `dataset_id` | 小写短横线 slug，如 `bsubtilis-termseq-author-2026` |
| `paper_title` | 论文标题原文 |
| `paper_publication_year` | 发表年份 |
| `pmid` / `doi` | 至少填一个；都有都填 |
| `species` / `strain` | 物种学名与菌株名，按论文原文写 |
| `assay` | 实验方法，如 `Term-seq`、`Rend-seq`、`dRNA-seq` |
| `sample_id_or_condition` | 样本或实验条件的简述 |
| `raw_data_accessions` | GEO/SRA/ENA 等登录号，多个用分号隔开 |
| `raw_or_supplement_url` | 数据或补充表的公开链接 |
| `endpoint_source_file` | 端点所在的补充表文件名（含 sheet 名更好） |
| `processing_status` | 此时一般填 `to_review` |
| `curator` / `intake_date` | 你的名字（或 GitHub 用户名）与登记日期（YYYY-MM-DD） |
| `blocker_or_note` | 目前发现的问题、疑点、缺失信息；没有问题填 `NA` |

### 4.2 可以暂时填 `NA` 的列

`pmc_or_fulltext_url`、`taxonomy_id`、`primary_evidence_class`、`published_reference_accession`、`reference_assembly`、`reference_sequence_accession_or_contigs`、`coordinate_convention`、`strand_definition`、`license_or_reuse_note`。

填 `NA` 的每一列，都要在 `blocker_or_note` 里写一句原因（例如“论文未注明参考组装版本，待核对 GEO 元数据”）。**填 NA 是允许的，编造是不允许的。**

## 5. 必须停下来标记的情况

出现以下任一情况，`processing_status` 标记为 `to_review` 或 `blocked`，停止后续标准化：

- 找不到任何公开的数据入口（补充表、登录号都没有）→ `blocked`；
- 论文没有写明菌株，或不同位置的菌株信息互相矛盾 → `to_review`；
- 找不到作者用的参考基因组版本，或补充表 contig 名与公开组装对不上 → `to_review`；
- 无法判断坐标是 0-based 还是 1-based，或无法判断是单点还是区间 → `to_review`；
- 无法判断链方向的编码含义（如作者用 `F/R`、`W/C` 而未给定义）→ `to_review`；
- 表里同时混有实验数据和预测结果，且无法分开 → `blocked`；
- 许可证或再分发条款明显不允许使用 → `blocked` 并记录条款出处。

标记停止不是失败。一份如实标记 `blocked` 的登记，比一个猜出来的坐标有用得多。

## 6. 核对菌株、参考组装、contig、坐标体系与链方向

这是入库最关键的一步，逐项做：

1. **菌株**：论文方法部分、GEO 样本描述、补充表表头三处应一致；不一致时全部如实记录，并标记 `to_review`。
2. **参考组装**：在 NCBI Assembly 用菌株名搜索，找到论文使用的组装（GCF/GCA 号）。优先看论文原文或 GEO 是否注明；注明了什么就记什么，不要用“最新版本”顶替。
3. **contig**：下载该组装的 assembly report 或 FASTA，列出全部 contig 名（含版本号，如 `NC_000964.3`）。把补充表里的 contig/chromosome 列与之逐一比对：名字必须逐字符一致，多 contig（染色体 + 质粒）必须全部存在。
4. **坐标体系**：判断作者坐标是 1-based 还是 0-based。常见线索：方法描述、坐标从 1 还是 0 开始、有无 `start = end` 的行、作者代码或 README。找不到明确证据时标记 `to_review`，不要按多数论文的习惯猜。
5. **链方向**：确认作者用 `+/-`、`F/R` 还是其他编码，及其确切含义（转录本链还是探针链）。

把结论写进来源登记表的 `published_reference_accession`、`reference_assembly`、`reference_sequence_accession_or_contigs`、`coordinate_convention`、`strand_definition`。

## 7. 建立端点表

**只有第 6 步全部核实的来源才建端点表。** 模板：`data/registry/templates/external_literature_endpoint_schema.tsv`（24 列）。

一行 = 一个端点（或作者表中一个可追溯的观测）。要点：

- `end_id`：`source_id + sample_id + contig + strand + 序号`，如 `BTED_EXT_2026_001_GSM8123456_NC_000964.3_F_000001`；
- `biological_coordinate_1based`：BTED 统一用 1-based 生物学坐标；若作者坐标是 0-based，转换后再填，并把转换规则写进 `coordinate_interpretation`；
- `bed_start_0based` = `biological_coordinate_1based - 1`，`bed_end_0based` = `biological_coordinate_1based`（单碱基 BED 规则）；
- `strand`：统一转成 `+` 或 `-`；
- `original_row_reference`：该行在作者原始表中的行号或键，保证任何人都能查回原文；
- 同一来源里不同 contig 的端点各自编号，**不做跨 contig 的任何匹配**。

## 8. 作者特有列怎么处理

标准端点表的 24 个核心列不随论文变化。作者表里的其他信息一律保留，规则是：

- read count、coverage、signal 值 → 填 `signal_or_score`（原样数值）；
- 作者的 TTS class、terminator 类型、置信度分级 → 填 `author_category`（原样标签）；
- 关联基因、locus tag、基因功能描述 → 填 `associated_gene_or_locus`；
- 结构预测（如 RNA 二级结构自由能）、预测分数 → 这是预测信息，填入 `note` 并注明“作者预测字段”，**不能据此把端点标成实验或预测以外的任何东西**；
- 一张表同时含实验端点和预测位点且作者已分开标注 → 拆成实验部分入端点表、预测部分记入 `data/audit/` 的排除记录；分不开 → 整个来源 `blocked`。

作者原始表文件本身**原样保存、一个单元格都不改**；标准化表是在它之外新建的文件。

## 9. 保存原始文件与记录

- 原始文件（补充表、下载的信号文件）保存在你自己本地的 `raw/` 或 `data/local/` 目录——这些路径已被 `.gitignore` 排除，**不会也不应进入 GitHub**；
- 计算每个原始文件的 SHA-256 并记录：

  ```bash
  shasum -a 256 文件名
  ```

- 在来源处理记录（Markdown，随 PR 提交）中写清：文件清单与 SHA-256、下载日期与链接、做过的每一步处理、用过的命令、失败与重试的原因；
- 问题记录格式：发现方式 → 影响 → 处理决定 → 解决证据 → 剩余风险。解决后的问题也保留原记录。

## 10. 建分支、提交、开 PR

```bash
git fetch origin
git checkout -b feature/source-BTED_EXT_2026_001 origin/main   # 基线以维护者通知为准
# ... 填写登记表 / 端点表 / 处理记录 ...
python3 scripts/validate_bted_templates.py                      # 模板结构校验
git add data/registry/ docs/
git commit -m "data: register BTED_EXT_2026_001 (<物种> <assay>)"
git push -u origin feature/source-BTED_EXT_2026_001
```

然后在 GitHub 上开 **Draft PR**，标题写清来源 ID 与文献。

### PR 必须附带的文件

1. 填好的来源登记表（TSV）；
2. 端点表（仅当核验通过；否则说明停在哪一步）；
3. 来源处理记录（Markdown）：原始文件清单 + SHA-256、核对过程、问题记录；
4. 校验脚本的 PASS 输出截图或文本；
5. 若改动了 `site/`，另附 `python3 scripts/validate-site.py` 的 PASS 结果。

### 一页式检查清单

提交前逐项打勾：

- [ ] 文献符合收录范围（细菌、实验数据、公开可得）
- [ ] 来源登记表 26 列齐全，`processing_status` 如实填写
- [ ] 缺失信息填 `NA` 且原因写进 `blocker_or_note`
- [ ] 菌株、参考组装、contig、坐标体系、链方向已核对并记录证据
- [ ] 端点表 `end_id` 含 source / sample / contig / strand / 序号
- [ ] 生物学坐标 1-based；BED 满足 `start = position - 1`、`end = position`
- [ ] 作者原始表原样保存，SHA-256 已记录
- [ ] 预测或混合证据未混入实验端点层
- [ ] 没有提交 xlsx / pdf / 测序文件 / 本地绝对路径
- [ ] `python3 scripts/validate_bted_templates.py` 通过
- [ ] 处理记录写清了做法、失败原因与剩余风险
- [ ] 在自己的 feature 分支上提交，开了 Draft PR

完成。评审人会在 PR 里回复修改意见或合并。
