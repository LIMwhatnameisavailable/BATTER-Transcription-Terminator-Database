# BTED 项目目录与协作规范

本文件说明仓库各目录的用途、命名与分支约定、统计口径、记录职责、仓库卫生规则和 PR 流程。

## 1. 目录用途

```
README.md                  项目说明与入口
docs/
  standards/               入库标准、协作者指南、字段字典、证据边界
  integration/             外部来源批次的交接与整合决定
  literature/              逐篇文献正式调研记录与总索引
  sources/                 按 source_id 组织的逐来源处理记录
  releases/                版本化发布说明
  diagrams/                可编辑 draw.io 入库与发布流程图
  legacy/                  历史探索笔记与早期项目报告（不作为标准结论）
  tasks/                   分支任务计划
  HANDOFF.md               跨人 / 跨模型的协作交接记录
  WORKLOG.md               按时间顺序的工作日志
data/
  registry/                来源级注册表、发布状态、schema 与 manifest
    templates/             来源登记表（26 列）与端点表（24 列）模板
    submissions/           协作者交接的来源登记快照（待审计）
    manifests/             每个来源的机器可读 manifest
  public/v0.2.0/           可公开的小型标准化数据（21 个来源 + 1 个 audit_only）
    records/               按 source_id 存放核心表、来源附表、BED、字段和 manifest
  audit/                   证据判断、冲突与排除记录（公开摘要；不含原始数据）
    legacy/                早期资料搜集阶段的小型审计快照
scripts/
  build_local_snapshot_release.py  本地快照构建器
  validate_bted_templates.py       模板结构校验
  validate_bted_release.py         发布数据、坐标、BED 与 checksum 校验
  build_v0_2_release.py            v0.2 双层数据构建器
  validate_bted_v0_2.py           v0.2 schema、外键、坐标和 checksum 校验
  build_jbrowse_release.py         21 来源 JBrowse 打包器
  validate_jbrowse_release.py      JBrowse 资产和配置校验
  build_v0_2_site.py               双语网站生成器
  validate-site.py                 站点产物校验
tests/
  test_bted_ingestion.py           发布回归测试
  test_bted_v0_2.py                v0.2 数据与网站回归测试
site/                      自动生成的双语 GitHub Pages 数据目录
```

新增目录的职责边界：

- `data/registry`：来源级注册表和 schema。只放登记表与小型元数据；
- `data/registry/submissions`：协作者交接的来源登记快照；它表示待审计，不等于已入库；
- `data/public`：可公开的小型、已审计标准化数据。进入条件见其 README；
- `data/audit`：可公开的证据判断、冲突与排除摘要；原始文件、私有信息和内部过程保留在本地；
- 本地 `raw/`、缓存、下载文件**不进入 GitHub**（`.gitignore` 已排除）。

## 2. 命名约定

### 文件与 ID

- 新来源 `source_id`：`BTED_EXT_年份_三位序号`（如 `BTED_EXT_2026_001`）；既有 `BATTER_S1_NNN` 不改；
- `dataset_id`：小写英文短横线 slug（如 `ecoli-termseq-author-2024`）；
- `end_id`：`source_id + sample_id + contig + strand + 序号`；
- 来源处理记录：`docs/sources/<source_id>/README.md`；机器可读 manifest 位于 `data/registry/manifests/<source_id>.json`。

### 分支

- 新文献接入：`feature/source-<source_id>`（如 `feature/source-BTED_EXT_2026_001`）；
- 标准与基础设施：`feature/<主题>`（如本分支 `feature/bted-v0.1-standards-and-structure`）；
- 不直接在 `main` 上提交；不 force push；不改写已推送历史。

## 3. 统计口径（全项目统一）

- **论文数**：13 篇原始研究文献（BATTER Table S1，PMID 清单见 `docs/legacy/project-reports/report_BATTER_supplementary.md`）；
- **来源记录数**：22 个来源记录（Table S1 中这些论文下的来源/物种数据记录）；
- **v0.2.0 记录数**：21 个公开来源共 28,399 条核心记录，另有 1 个 `audit_only` 来源；
- **样本数 / 端点数**：按注册表与端点表逐来源统计，引用时注明版本与口径；
- 论文数与来源记录数单位不同，**不能混写为同一个“数据集数量”**；
- 未完成逐来源重新审计前，任何公开页面不得声称“所有 22 个来源均已公开发布”或“所有端点均为功能验证终止子”。

## 4. 记录职责

| 文件 | 职责 | 何时更新 |
|------|------|----------|
| 来源处理记录 | 该来源的全部事实：证据层、参考版本、坐标体系、checksum、问题与剩余风险 | 处理该来源的每一步 |
| `docs/WORKLOG.md` | 按时间记录任务、完成内容、验证命令与结果 | 每个任务完成时 |
| `docs/HANDOFF.md` | 给下一位协作者 / 模型的交接：当前状态、待决事项、下一步 | 换人、换模型、跨阶段时 |
| `data/audit/` | 证据排除、冲突判定、blocked 原因留档 | 发生相应判断时 |

问题记录格式：发现方式 → 影响 → 处理决定 → 解决证据 → 剩余风险。已解决的问题保留原记录。

## 5. 不允许上传的内容

`.gitignore` 已排除以下类型，请勿以任何方式强制提交：

- macOS 垃圾文件：`.DS_Store`、`__MACOSX/`、`._*`；
- 本地数据目录：`data/local/`、`raw/`；
- 原始测序与比对文件：`*.fastq(.gz)`、`*.fq(.gz)`、`*.bam`、`*.bai`、`*.cram`、`*.crai`、`*.bigWig`、`*.bw`；
- 出版商工作簿与文档：`*.xlsx`、`*.pdf`、`*.zip`（按 DOI / 登录号引用，只链接不复制）；
- 缓存、临时目录与本地环境文件（`__pycache__/`、`.env`、`.venv/`、`node_modules/` 等）；
- 凭据、API key、令牌、本地绝对路径、未发表数据。

## 6. PR 审查与合并流程

1. **开分支**：按第 2 节命名，从约定的基线分支创建（一律先 `git fetch origin`，只用 fast-forward 更新）；
2. **做改动**：遵循 SOP 与字段字典；改动范围保持小而可评审；
3. **本地验证**：先运行 `python3 scripts/validate_repo_layout.py`，再按改动运行模板、v0.1 回归、v0.2、JBrowse、站点和 unittest 校验；完整命令见根目录 README；
4. **开 Draft PR**：描述写清——本次建立了什么、没有迁移 / 没有做什么、仍需确认的问题、验证命令与结果；
5. **评审要点**：证据分层是否正确、坐标规则是否遵守、统计口径是否混写、是否夹带禁传文件、是否有本地路径或凭据；
6. **合并**：评审通过后由维护者合并；数据类 PR 一律逐来源审计后合并，不批量打包；
7. **合并后**：更新 WORKLOG / HANDOFF；被合并的 feature 分支可删除，来源 ID 与处理记录永久保留。
